# 작업 로그: 타이틀 화면에서 한 곡 플레이까지 (issue #13)

* 이슈: [#13](https://github.com/reexec/reDMP2/issues/13) (연계 HLE: [reexec/repsp#73](https://github.com/reexec/repsp/issues/73))
* 설계: [20261121-i013-song-play.md](../design/20261121-i013-song-play.md)
* 브랜치: `i013-song-play`

## 1. 진행 (확인됨)

* 출발점(v0.0.6): MODE SELECT에서 4B를 고르면 로딩 화면에서 `sceKernelGetSystemTime` 미구현으로 멈춤(1,178프레임).
* repsp #73에서 `sceKernelGetSystemTime`, `sceKernelSysClock2USec`를 구현한 뒤 곡 선택, 곡 플레이, 실패 결과(GAMEOVER) 화면까지 감. 이 저장소의 lift 수정은 필요 없었다(디스패치 미스 0).
* 빌드: `build\win64-release-ffmpeg`(`REDMP2_CODEC_FFMPEG=ON`, `FFMPEG_ROOT=third_party/repsp/third_party/_ffmpeg`). 플러그인이 실행 파일 옆에서 자동으로 읽힌다.

## 2. 리뷰어 재현 (`--max-vblanks 9000`)

* 입력: v0.0.5 타이틀 입력 뒤 `1800 START`(타이틀), `2100 CIRCLE`(4B), `2400 CIRCLE`, `2900 CIRCLE`, `3100 CIRCLE`(곡 선택·시작). 각 입력 10 vblank 뒤 `NONE`. 전체 목록은 repsp #73 작업 로그 §2.
* 결과: `(e) VBlank limit reached`, 종료 코드 `0`, 새 미구현 NID와 디스패치 미스 `0`, 3,217프레임(평균 46.69 ms).
* 화면: 곡 선택(`4B STAGE 1`), 곡 플레이(배경 영상, 4레인 기어, 노트, 판정), 게이지 소진 뒤 `GAMEOVER` 메뉴(RESTART / MUSIC SELECT / EXIT). repsp #73 반복 4에서 EXIT가 타이틀로 돌아감을 확인했다. 덤프는 커밋하지 않았다.
* 정적 대조(`tools/import_coverage.py`, repsp v0.0.34): 161 → **163** / 229.

## 3. 관찰 (정지 아님, 후속 issue)

1. 곡 선택 화면 오른쪽 곡 목록 글자가 세로로 눌리고 겹친다(사용자가 창 모드에서도 확인).
2. headless에서 오디오 언더런 4,601회(9,000 vblank). 소프트웨어 렌더링으로 프레임이 느린 탓일 수 있어 창 모드에서 다시 잰다.

# Work log: from the title screen to one played song (issue #13)

* Issue: [#13](https://github.com/reexec/reDMP2/issues/13) (paired HLE: [reexec/repsp#73](https://github.com/reexec/repsp/issues/73))
* Design: [20261121-i013-song-play.md](../design/20261121-i013-song-play.md)
* Branch: `i013-song-play`

## 1. Progress (confirmed)

* Starting point (v0.0.6): choosing 4B in MODE SELECT stopped on the loading screen at unimplemented `sceKernelGetSystemTime` (frame 1,178).
* After repsp #73 implemented `sceKernelGetSystemTime` and `sceKernelSysClock2USec`, the run reaches song select, song play and the failed result screen (GAMEOVER). No lift fix was needed here (no dispatch miss).
* Build: `build\win64-release-ffmpeg` (`REDMP2_CODEC_FFMPEG=ON`, `FFMPEG_ROOT=third_party/repsp/third_party/_ffmpeg`). The plugin loads automatically from next to the executable.

## 2. Reviewer reproduction (`--max-vblanks 9000`)

* Input: after the v0.0.5 title inputs, `1800 START` (title), `2100 CIRCLE` (4B), then `2400 CIRCLE`, `2900 CIRCLE`, `3100 CIRCLE` (song select and start). Each is followed by `NONE` 10 vblanks later; the full list is in repsp #73's work log §2.
* Result: `(e) VBlank limit reached`, exit code `0`, no new unimplemented NID and no dispatch miss, 3,217 frames (mean 46.69 ms).
* Screens:
  * song select (`4B STAGE 1`)
  * song play (background video, 4-lane gear, notes, judgements)
  * after the gauge runs out, the `GAMEOVER` menu (RESTART / MUSIC SELECT / EXIT)

  repsp #73 iteration 4 confirmed that EXIT returns to the title. Dumps are not committed.
* Static match (`tools/import_coverage.py`, repsp v0.0.34): 161 → **163** of 229.

## 3. Observations (not stops; follow-up issues)

1. On the song select screen, the song list text on the right is squashed vertically and overlaps (the user confirmed it in windowed mode too).
2. 4,601 audio underruns in 9,000 headless vblanks. This may come from slow software-rendered frames; it will be measured again in windowed mode.
