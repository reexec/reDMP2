# 설계: UMD 교체로 하는 링크 디스크 (issue #23)

## 1. 요구사항

* 사용자 결정(2026-11-24): 링크 디스크는 UMD 교체 방식으로 구현한다. 디스크는 `roms/<DISC_ID>/`에 둔다(v0.0.11, #21).
* 빌드와 실행에는 DMP2만 필요하다. 다른 디스크가 없으면 링크 디스크만 쓸 수 없고 나머지는 그대로다.
* 디스크 ID만 속이는 방식은 쓰지 않는다. 사용자가 가진 다른 디스크의 덤프를 실제로 "넣는다".
* repsp 쪽은 [reexec/repsp#79](https://github.com/reexec/repsp/issues/79)다.

## 2. 지금까지 확인한 것 (리뷰어, 정적 분석)

* **디스크 식별** `0x0886EA94`: `disc0:/PSP_GAME/PARAM.SFO`의 296번 오프셋에서 16바이트(디스크 ID)를 읽어 다음 값을 돌려준다.

  | 디스크 ID | 반환값 |
  |---|---|
  | `ULKS46050` (DJMAX Portable 1) | 0 |
  | `ULKS46059` (제목 미확인) | 1 |
  | `ULKS46116` (DMP2) | 2 |
  | 그 밖 | 다른 값 |

  `PARAM.SFO` 안의 위치에 의존하므로, 덤프의 `PARAM.SFO`를 그대로 읽게 해야 한다.
* **교체 흐름**: `0x0886DCE0`, `0x0886DE40` 근처가 디스크 상태를 확인한다.
  * `sceUmdGetDriveStat`로 상태를 보고, `sceUmdCheckMedium`으로 디스크가 있는지 본다.
  * 그다음 식별 함수를 부른다.
  * `0x0886EA70`이 `sceUmdReplaceProhibit`를 부른다. `sceUmdReplacePermit`도 import되어 있다.
  * 세 함수 모두 repsp에 아직 없다.
* **해금 목록**: `0x0886E7BC`가 DMP1이면 `discstock_dmp1.csv`, `ULKS46059`면 `discstock_dmpi.csv`를 읽는다.
* **연동 데이터**: DMP2 데이터 안에 `system/linkdisc_game.mp`, `system/linkdisc_{kr,en,jp}.mp`가 있다(`0x088BE448` 근처).
  * 플레이 장면 `0x08853628`은 `ms0:/PSP/SAVEDATA/ULKS46116DATA0/linkdisc_game.mp`를 `system/game.mp`와 함께 읽는다.
  * 연동 곡 데이터를 메모리 스틱에 꺼내 두는 것으로 보인다(**추정**, `CSaveData::createExtFile` 문자열).
* **추정**: DMP1 디스크에서는 `PARAM.SFO`만 읽는다. DMP1 디스크에는 링크 관련 파일이 없다.

## 3. 1단계: 흐름 측정 (먼저, 리뷰 후 2·3단계)

`docs/analysis/link-disc.md`(한국어 먼저, 영어 아래)에 다음을 쓴다. 항목마다 확인됨/추정과 근거를 단다.

1. 게임 안에서 링크 디스크 메뉴의 위치와 진행 화면. 메뉴 문구, 안내 메시지, 버튼 순서를 적는다. 타이틀에 링크 디스크 배경(`title_bg_linkdisc`)이 있다.
2. 게임이 부르는 UMD 함수의 순서와 기대값.
   * `ReplacePermit`/`Prohibit`를 부르는 시점
   * `GetDriveStat`의 어떤 비트를 보는지(없음, 있음, 바뀜, 준비 등)
   * `CheckMedium`의 반환값 의미
   * 교체를 기다리는 방식(폴링 또는 `WaitDriveStat*`)
3. 교체된 디스크에서 읽는 파일 전부. `PARAM.SFO` 말고 더 있는지 확인한다.
4. DMP2로 되돌린 뒤 하는 일.
   * `linkdisc_game.mp`를 쓰는 시점, 크기, 원본(DMP2 아카이브의 어느 항목인지)
   * 세이브(`SD*.BIN`)에 남는 표시
5. 해금되는 내용: `discstock_dmp1.csv`가 가리키는 곡과 모드.
6. `ms0:/PSP/SAVEDATA/...` 직접 쓰기와 `sceUtility` 세이브 위치(`--save-dir`)의 관계. 지금 reDMP2는 두 곳이 다른 폴더다.

방법:
* 생성 코드를 읽는다.
* 실행해서 링크 디스크 메뉴까지 간다. 교체 전에 미구현 NID로 멈추는 지점을 확인한다.
* 필요하면 `REPSP_HLE_TRACE`와 `REDMP2_MEM_DUMP`를 쓴다.
* 교체 이후 흐름은 정적 분석으로 쓰고 "교체 모델 뒤 확인"으로 표시한다.

**1단계가 끝나면 멈추고 보고한다.**

## 4. 2단계: repsp #79 UMD 교체 모델 (요지, 상세는 repsp 설계)

* 드라이브 상태: 디스크 없음 → 있음(바뀜) → 준비. 상태 비트 값은 PSPSDK `pspumd.h`를 따른다.
* 함수:
  * `sceUmdReplacePermit`/`Prohibit`: 교체 허용 상태를 둔다.
  * `sceUmdCheckMedium`: 디스크가 있으면 0이 아닌 값.
  * `GetDriveStat`/`WaitDriveStat*`: 상태 변화를 반영하고, 대기를 깨운다.
* 호스트 API:
  * 교체 허용 여부를 묻는다.
  * 디스크 꺼내기와 다른 폴더 넣기. 넣으면 `disc0:`/`umd0:`가 그 폴더로 다시 마운트된다.
  * 상태 질의.
* 꺼낸 동안 `disc0:` 접근은 실패한다. 열려 있던 파일의 처리는 1단계 측정을 보고 정한다.
* 타이틀 중립. probe로 상태 전이, 대기 깨우기, 재마운트, 허용 상태를 검사한다.

## 5. 3단계: reDMP2

* OSD에 "Link disc" 절을 둔다.
  * #21이 찾은 링크 디스크 후보(주 디스크가 아닌 `roms/` 아래 디스크)를 제목·ID로 보여 준다.
  * "넣기"와 "DMP2 다시 넣기" 버튼을 둔다.
  * 게임이 교체를 허용하지 않을 때는 버튼을 끄고 이유를 보여 준다.
  * 후보가 없으면 "`roms/`에 디스크가 없음" 안내만 보인다.
* 1단계 6번 결과에 따라 `ms0:/PSP/SAVEDATA`와 `--save-dir`를 같은 곳으로 맞춘다. 기존 세이브가 있으면 옮기는 방법도 함께 정한다.
* 가능하면 `--input-script` 같은 자동 검증 수단을 둔다. 예: 지정 vblank에 디스크를 넣는 명령줄 옵션.

### 5.1 1단계 리뷰 뒤 결정 (2026-11-24)

분석은 [`docs/analysis/link-disc.md`](../analysis/link-disc.md)에 있다. §2의 추정 두 가지를 고친다.

* DMP1 디스크에서는 `PARAM.SFO`뿐 아니라 `USRDIR/all.mp`·`all2.mp`도 연다.
* 링크 디스크 모드에서는 DMP1을 넣은 채로 DMP1 곡을 DMP2 엔진으로 플레이한다.
* 따라서 DMP1 덤프는 `PSP_GAME/` 전체가 있어야 한다.
* `linkdisc_*.mp`는 교체 **전에** 세이브 유틸리티로 메모리 스틱에 꺼내 둔다.

결정:

* **repsp**: 한 브랜치에서 둘을 진행한다. 설계는 repsp `docs/design/20261124-i079-umd-swap.md`다.
  * [#79](https://github.com/reexec/repsp/issues/79): UMD 교체 모델
  * [#80](https://github.com/reexec/repsp/issues/80): 세이브 유틸리티 모드 12/13/15/17/19/22, `sceIoDevctl` 여유 공간, 휘발성 메모리 잠금
* **저장 위치 하나로**: `--save-dir <dir>`은 이제 메모리 스틱 루트(`ms0:`)를 뜻한다.
  * 세이브 유틸리티의 저장 위치는 `<dir>/PSP/SAVEDATA`다.
  * 기본값은 `<user_data>/ms0`이다.
  * 예전 기본 위치(`<user_data>/savedata`)에 세이브가 있고 새 위치에 없으면, 처음 실행할 때 새 위치로 옮기고 로그를 남긴다.
  * README와 가이드에 바뀐 뜻을 적는다.
* **디스크 목록**: #21의 링크 디스크 후보(주 디스크가 아닌 `roms/` 아래 디스크) 중 `PSP_GAME/USRDIR`가 있는 것만 보인다.
* **OSD**: §5의 Link disc 절. 버튼은 repsp 호스트 API의 허용 상태를 따른다. 넣기 전에 꺼내기를 자동으로 한다.
* **자동 검증**: `--insert-disc <vblank>:<disc_id|main>`(여러 번 가능) 명령줄 옵션을 둔다. 입력 스크립트와 함께 쓰면 headless로 끝까지 검증할 수 있다.

## 6. 검증

1. DMP1(`roms/ULKS46050/`)으로 링크 디스크를 끝까지 진행한다.
   * 해금 화면과 해금된 곡을 덤프로 확인한다.
   * 다시 실행해도 해금이 유지된다(세이브).
2. DMP1이 없을 때 OSD 안내가 맞고, 나머지 동작이 그대로다.

4. CTest: 생성 코드 없이 Win64 Debug/Release, 생성 코드 포함 Release. Linux는 CI.
5. 사용자가 창 모드에서 확인한다.

# Design: link disc via UMD swap (issue #23)

## 1. Requirements

* User decision (2026-11-24): link disc is implemented as a UMD swap, with discs under `roms/<DISC_ID>/` (v0.0.11, #21).
* Build and run need only DMP2. Without other discs only link disc is unavailable.
* No faking of the disc ID alone: the user's own dump of the other disc is actually "inserted".
* The repsp side is [reexec/repsp#79](https://github.com/reexec/repsp/issues/79).

## 2. Confirmed so far (reviewer, static analysis)

* **Disc identification** `0x0886EA94`: reads 16 bytes (the disc ID) at offset 296 of `disc0:/PSP_GAME/PARAM.SFO` and returns the values in the table above:
  * `ULKS46050` (DJMAX Portable 1) → 0
  * `ULKS46059` (title unconfirmed) → 1
  * `ULKS46116` (DMP2) → 2
  * anything else → another value

  It depends on the position inside `PARAM.SFO`, so the dump's own `PARAM.SFO` must be read as is.
* **Swap flow**: code around `0x0886DCE0` and `0x0886DE40` checks the disc state.
  * It reads the state with `sceUmdGetDriveStat` and checks for a disc with `sceUmdCheckMedium`.
  * Then it calls the identification function.
  * `0x0886EA70` calls `sceUmdReplaceProhibit`, and `sceUmdReplacePermit` is imported too.
  * None of the three is in repsp yet.
* **Unlock list**: `0x0886E7BC` reads `discstock_dmp1.csv` for DMP1 and `discstock_dmpi.csv` for `ULKS46059`.
* **Link data**: DMP2's own data holds `system/linkdisc_game.mp` and `system/linkdisc_{kr,en,jp}.mp` (around `0x088BE448`).
  * The play scene `0x08853628` reads `ms0:/PSP/SAVEDATA/ULKS46116DATA0/linkdisc_game.mp` alongside `system/game.mp`.
  * The linked songs appear to be extracted to the Memory Stick (**inferred**, from the `CSaveData::createExtFile` string).
* **Inferred**: only `PARAM.SFO` is read from the DMP1 disc, which has no link files of its own.

## 3. Phase 1: measure the flow (first; phases 2 and 3 after review)

Write `docs/analysis/link-disc.md` (Korean first, English below), marking each item confirmed/inferred with evidence:

1. Where the link disc menu is in the game and its screens: menu text, prompts and button order. The title has a link disc background (`title_bg_linkdisc`).
2. The order of UMD calls and the values the game expects:
   * when `ReplacePermit`/`Prohibit` are called
   * which `GetDriveStat` bits it checks (absent, present, changed, ready, ...)
   * what `CheckMedium`'s result means
   * how it waits for the swap (polling or `WaitDriveStat*`)
3. Every file read from the swapped disc, beyond `PARAM.SFO` if any.
4. What happens after switching back to DMP2:
   * when `linkdisc_game.mp` is written, its size, and its source (which entry of the DMP2 archive)
   * what is marked in the save (`SD*.BIN`)
5. What gets unlocked: the songs and modes `discstock_dmp1.csv` points to.
6. How direct writes to `ms0:/PSP/SAVEDATA/...` relate to the `sceUtility` save location (`--save-dir`). Today these are different folders in reDMP2.

Method:
* Read the generated code.
* Run up to the link disc menu and find where it stops on an unimplemented NID before the swap.
* Use `REPSP_HLE_TRACE` and `REDMP2_MEM_DUMP` where needed.
* Write the post-swap flow from static analysis, marked "to confirm after the swap model".

**Stop and report when phase 1 is done.**

## 4. Phase 2: repsp #79 UMD swap model (summary; details in the repsp design)

* Drive states: no disc → present (changed) → ready, with bit values from PSPSDK `pspumd.h`.
* Functions:
  * `sceUmdReplacePermit`/`Prohibit` keep a replacement-allowed state.
  * `sceUmdCheckMedium` returns nonzero when a disc is present.
  * `GetDriveStat`/`WaitDriveStat*` reflect state changes and wake waiters.
* Host API:
  * ask whether replacement is allowed
  * eject, and insert another folder; inserting remounts `disc0:`/`umd0:` to that folder
  * query the state
* While ejected, `disc0:` access fails. How open files are handled is decided from phase 1.
* Title-neutral. Probes check state transitions, waking waiters, remounting, and the permit state.

## 5. Phase 3: reDMP2

* An OSD "Link disc" section:
  * lists the link disc candidates #21 finds (discs under `roms/` other than the main one) by title and ID
  * has "Insert" and "Reinsert DMP2" buttons
  * disables the buttons with the reason shown while the game does not permit replacement
  * shows only a "no discs in `roms/`" note when there are no candidates
* Depending on phase 1 item 6, `ms0:/PSP/SAVEDATA` and `--save-dir` are made the same place, with a way to move existing saves.
* If possible, an automated check like `--input-script`, for example a command-line option that inserts a disc at a given vblank.

### 5.1 Decisions after the phase 1 review (2026-11-24)

The analysis is in [`docs/analysis/link-disc.md`](../analysis/link-disc.md). It corrects two inferences in §2:

* From the DMP1 disc, the game opens not only `PARAM.SFO` but also `USRDIR/all.mp` and `all2.mp`.
* In link disc mode, DMP1 stays inserted and its songs are played with DMP2's engine.
* So the DMP1 dump needs the whole `PSP_GAME/`.
* `linkdisc_*.mp` are extracted to the Memory Stick through the savedata utility **before** the swap.

Decisions:

* **repsp**: two issues on one branch, designed in repsp `docs/design/20261124-i079-umd-swap.md`:
  * [#79](https://github.com/reexec/repsp/issues/79): the UMD swap model
  * [#80](https://github.com/reexec/repsp/issues/80): savedata utility modes 12/13/15/17/19/22, `sceIoDevctl` free space, and the volatile memory lock
* **One save location**: `--save-dir <dir>` now means the Memory Stick root (`ms0:`).
  * Savedata utility storage is `<dir>/PSP/SAVEDATA`.
  * The default is `<user_data>/ms0`.
  * If saves exist in the old default (`<user_data>/savedata`) and none in the new one, they are moved there on first run, with a log line.
  * README and guides describe the new meaning.
* **Disc list**: of #21's link disc candidates (discs under `roms/` other than the main one), only those with `PSP_GAME/USRDIR` are shown.
* **OSD**: the Link disc section of §5. Buttons follow the repsp host API's permit state, and inserting ejects first automatically.
* **Automated check**: a command-line option `--insert-disc <vblank>:<disc_id|main>` (repeatable). With an input script it allows a full headless check.

## 6. Verification

1. Complete link disc with DMP1 (`roms/ULKS46050/`).
   * Confirm the unlock screen and the unlocked songs from dumps.
   * The unlock persists across runs (save).
2. Without DMP1, the OSD note is right and everything else is unchanged.
3. Swapping is impossible in scenes that do not permit replacement.
4. CTest: Win64 Debug/Release without generated code, and Release with it. Linux in CI.
5. The user checks in windowed mode.
