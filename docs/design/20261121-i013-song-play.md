# 설계: 타이틀 화면에서 한 곡 플레이까지 (issue #13)

## 1. 요구사항

* 타이틀 화면에서 시작해 모드 선택과 곡 선택을 거쳐 한 곡을 끝까지 플레이하고, 결과 화면(클리어 또는 실패)에 닿는다.
* HLE는 repsp [#73](https://github.com/reexec/repsp/issues/73)에서, lift 쪽 결함은 이 저장소에서 고친다. 끝나면 repsp 고정점을 옮기고 결과 화면을 기록한다.
* 실행은 FFmpeg 플러그인 빌드(`build\win64-release-ffmpeg`, `REDMP2_CODEC_FFMPEG=ON`)로 한다. 고정한 FFmpeg는 `third_party\repsp\third_party\_ffmpeg`에 있고, git이 무시한다. 플러그인은 실행 파일 옆에 놓여 자동으로 읽힌다.

## 2. 출발점 (확인됨, v0.0.6)

* 타이틀까지의 입력(v0.0.5 작업 로그 §3) 뒤에 `1800 START`를 넣으면 MODE SELECT 화면(4B, EASY MODE)이 표시된다.
* `2100 CIRCLE`로 4B를 고르면 `4BUTTONS PLAY` 로딩 화면이 나온다.
* 거기서 `sceKernelGetSystemTime` 미구현으로 멈춘다(1,178프레임, 2,456 vblank).

## 3. 이 저장소의 일

* 디스패치 미스가 나오면 lift 누락인지 확인한다. 지금까지 세 번(`0007`, `0008`, `0011`) 모두 코드가 조립한 함수 포인터를 놓친 것이었다. 근거를 확인한 뒤 로컬 패치로 고치고, 고친 뒤에도 함수 수, 커버리지, `lift_audit`(0/0), reDMP1 PRX 결과(9,004)를 비교한다.
* 플레이 중 입력 처리는 이미 있는 `--input-script`로 충분하다. 자동 연주(reDMP1 `--autoplay`)는 이 issue의 범위가 아니다.
* 작업 로그에 다음을 남긴다:
  * 입력 스크립트
  * 결과 화면 프레임
  * 곡 플레이 중 관찰한 이상(음악·노트 동기, 렌더링)

  덤프는 커밋하지 않는다.

## 4. 검증

1. 결과 화면에 닿는다. 그때 새 미구현 NID와 디스패치 미스가 0이다.
2. lift 패치가 추가되면 위 §3의 수치를 비교한다.
3. CTest: 생성 코드 없이 Win64 Debug/Release, 생성 코드 포함 Release. Linux는 CI.

# Design: from the title screen to one played song (issue #13)

## 1. Requirements

* Start at the title screen, go through mode select and song select, play one song to the end, and reach its result screen (cleared or failed).
* HLE is done in repsp [#73](https://github.com/reexec/repsp/issues/73); lift defects are fixed here. Afterwards the repsp pin moves and the result screen is recorded.
* Runs use the FFmpeg plugin build (`build\win64-release-ffmpeg`, `REDMP2_CODEC_FFMPEG=ON`).
  * The pinned FFmpeg is in `third_party\repsp\third_party\_ffmpeg`, ignored by git.
  * The plugin sits next to the executable and loads automatically.

## 2. Starting point (confirmed, v0.0.6)

* After the inputs up to the title (v0.0.5 work log §3), `1800 START` shows MODE SELECT (4B, EASY MODE).
* `2100 CIRCLE` picks 4B and shows the `4BUTTONS PLAY` loading screen.
* There the run stops on unimplemented `sceKernelGetSystemTime` (frame 1,178, vblank 2,456).

## 3. This repository's part

* A dispatch miss is first checked for a lift miss.
  * All three so far (`0007`, `0008`, `0011`) were code-built function pointers the lifter missed.
  * Once confirmed, it is fixed with a local patch.
  * After the fix, compare the function count, coverage, `lift_audit` (0/0) and reDMP1's PRX result (9,004).
* The existing `--input-script` is enough for input during play. Autoplay (reDMP1's `--autoplay`) is out of scope.
* The work log records:
  * the input script
  * the result-screen frame
  * any anomalies seen during play (music and note sync, rendering)

  Dumps are not committed.

## 4. Verification

1. The result screen is reached, with no new unimplemented NID and no dispatch miss.
2. If a lift patch is added, compare the numbers in §3.
3. CTest: Win64 Debug/Release without generated code, and Release with it. Linux in CI.
