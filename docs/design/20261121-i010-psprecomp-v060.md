# 설계: psprecomp upstream v0.6.0으로 이동 (issue #10)

## 1. 배경

* upstream psprecomp의 최신은 v0.6.0(`14749c1`)이다. 지금 고정점은 `5ca18fa`(v0.5.0 뒤 22커밋)다.
* [reexec/reDMP1#62](https://github.com/reexec/reDMP1/issues/62)(reDMP1 v0.0.31)에서 같은 이동을 끝냈다. 설계·측정은 그 문서([reDMP1 설계 i062](https://github.com/reexec/reDMP1/blob/main/docs/design/20261121-i062-psprecomp-v060.md))를 따른다.
* v0.6.0에 들어간 이 저장소의 로컬 패치(reDMP1에서 가져온 것):

  | 로컬 패치 | upstream |
  |---|---|
  | `0001` (`--base`, `relocate`) | #36 |
  | `0003` (링크하는 `jalr` 뒤를 이어 감) | #31 |
  | `0004` (자기 본문 주소로 가는 `j`는 goto) | #35 |
  | `0006` (루프 훅) | #38 |

* 생성 코드를 바꾸는 upstream 변경은 #32 하나다. 게스트 호출의 복귀 지점 프레임을 생성 본문 대신 런타임의 `psp_call_guest_fn(fn, ret)`·`psp_call_guest_addr(addr, ret)`가 쌓고 내린다.
* `0005`(`--trampoline`, upstream #37 미머지)는 reDMP1이 v0.6.0 위로 rebase했다(`d9278d2`). trampoline 모드에서도 게스트 호출은 #32 방식이다.
* 이 저장소에만 있는 `0007`~`0011`(`ET_EXEC` 포인터 스캔, import 꼬리 점프, import stub 제외, 레지스터 추적)은 upstream에 없다. 제출은 보류 중이다(사용자 결정). 머지된 #36에도 `0007`이 고친 결함(`if (an->scan_calls && !an->image)`)이 그대로 있다.

## 2. 사전 확인 (확인됨)

v0.6.0의 `tools/allegrexrecomp`에 reDMP1의 `0005`와 이 저장소의 `0007`~`0011`을 차례로 `git apply --check`하면 모두 충돌 없이 적용된다. 그래도 줄 번호·문맥이 v0.6.0에 정확히 맞도록 다시 만든다.

## 3. 변경

1. **submodule**: `third_party/psprecomp` → `14749c1`(v0.6.0).
2. **로컬 패치**:
   * `0001`, `0003`, `0004`, `0006`을 지운다.
   * `0005`는 reDMP1의 `patches/psprecomp/0005-emit-trampoline.patch`(v0.6.0 판)로 바꾼다.
   * `0007`~`0011`은 v0.6.0 + `0005` 위에 차례로 적용해 커밋한 뒤 `git format-patch`로 다시 만든다. 내용은 바꾸지 않는다.
   * `CMakeLists.txt`의 패치 목록과 `patches/psprecomp/README.md`(기준 커밋, upstream 상태 표, 패치 설명)를 맞춘다.
3. **ABI 어댑터**: reDMP1 v0.0.31의 변경을 그대로 가져온다.
   * `src/recomp_abi/dispatch.c`에 `PSP_NOINLINE psp_call_guest_fn`·`psp_call_guest_addr`를 둔다. 프레임을 쌓고, `psp_run(fn)` 또는 `psp_dispatch(addr)`를 부르고, 프레임을 내린다. unwind는 자기 복귀 지점을 겨눈 것만 지운다.
   * `src/recomp_abi/README.md`의 표를 고친다.
   * 파생 주석(`cpu.c`, `dispatch.c`, `vfpu.c`)을 `14749c1`로 고친다. 그 전에 upstream `5ca18fa..14749c1`의 해당 원본 변경을 확인한다.
4. **probe**: reDMP1의 `tests/recomp_abi_probe.cpp` 9번 항목을 가져온다. tail 사슬 완주, 프레임 복구, unwind 정리·보존, 미등록 주소 miss를 검사한다.
5. **다시 생성**: 새로 빌드한 lifter로 `scripts/recomp/regenerate.py`를 돌린다. 출력된 lifter 경로가 방금 빌드한 것인지 확인한다. 생성 코드는 커밋하지 않는다.
6. 문서: `THIRD_PARTY_NOTICES.md`의 psprecomp 고정점, `docs/analysis/executable.md`의 lifter 기준.

## 4. 검증

1. 생성 코드의 차이를 지금 것과 비교한다. 주소를 지우고 줄 빈도로 센다. 기대는 reDMP1 §2와 같은 종류의 치환뿐이다(`psp_run(psp_func_X)`·`psp_import_X()`·`psp_dispatch(_t)` → `psp_call_guest_fn`/`psp_call_guest_addr`, 헤더의 `PSP_CALL_BEGIN`/`END`). 그 밖의 차이가 있으면 원인을 적는다.
2. lift 수치가 그대로다: 함수 7,982, 진입점 28,109, `.text` 759,072 B, `lift_audit` 0/0. 이 저장소의 lifter로 reDMP1 PRX를 lift한 결과(읽기 전용 측정)는 reDMP1 v0.0.31의 결과(함수 9,024)와 같아야 한다(`0007`~`0011`이 PRX 경로를 바꾸지 않음).
3. CTest: 생성 코드 없이 Win64 Debug/Release, 생성 코드 포함 Release. Linux는 CI.
4. 게임: v0.0.5의 입력 스크립트(`--max-vblanks 2400`)로 Release와 Debug(생성 코드 최적화 없음) 모두 타이틀 화면에 닿는다. 디스패치 미스 0, 스택 넘침 없음.
5. 같은 실행에서 프레임 간격 평균을 v0.0.5와 비교한다(호출마다 함수 하나를 더 거치므로).

# Design: move to psprecomp upstream v0.6.0 (issue #10)

## 1. Background

* Upstream psprecomp's latest release is v0.6.0 (`14749c1`). The current pin is `5ca18fa`, 22 commits after v0.5.0.
* [reexec/reDMP1#62](https://github.com/reexec/reDMP1/issues/62) (reDMP1 v0.0.31) made the same move. The design and measurements follow that document ([reDMP1 design i062](https://github.com/reexec/reDMP1/blob/main/docs/design/20261121-i062-psprecomp-v060.md)).
* This repository's local patches (carried from reDMP1) that are now in v0.6.0 (table above): `0001` (#36), `0003` (#31), `0004` (#35), `0006` (#38).
* The one upstream change that alters generated code is #32. The return-site frame of a guest call is pushed and popped by the runtime's `psp_call_guest_fn(fn, ret)` / `psp_call_guest_addr(addr, ret)` instead of the generated body.
* `0005` (`--trampoline`, upstream #37, not merged) was rebased onto v0.6.0 by reDMP1 (`d9278d2`). Guest calls use the #32 form in trampoline mode too.
* `0007` to `0011` exist only here:
  * the `ET_EXEC` pointer scan
  * the import tail jump
  * import stub exclusion
  * register tracking

  They are not upstream, and submission is on hold (user decision). Merged #36 still carries the defect `0007` fixes (`if (an->scan_calls && !an->image)`).

## 2. Pre-check (confirmed)

reDMP1's `0005` and this repository's `0007` to `0011`, applied in order with `git apply --check` to v0.6.0's `tools/allegrexrecomp`, all apply without conflict. They are still regenerated so line numbers and context match v0.6.0 exactly.

## 3. Changes

1. **Submodule**: `third_party/psprecomp` → `14749c1` (v0.6.0).
2. **Local patches**:
   * Remove `0001`, `0003`, `0004`, `0006`.
   * Replace `0005` with reDMP1's `patches/psprecomp/0005-emit-trampoline.patch` (the v0.6.0 version).
   * Regenerate `0007` to `0011`: apply them in order on v0.6.0 + `0005`, commit each, then `git format-patch`. Content is unchanged.
   * Update the patch list in `CMakeLists.txt` and `patches/psprecomp/README.md` (base commit, upstream table, descriptions).
3. **ABI adapter**: take reDMP1 v0.0.31's change as is.
   * `src/recomp_abi/dispatch.c` gets `PSP_NOINLINE psp_call_guest_fn` / `psp_call_guest_addr`. Each pushes a frame, calls `psp_run(fn)` or `psp_dispatch(addr)`, then pops the frame. Only an unwind aimed at its own return site is cleared.
   * Update the table in `src/recomp_abi/README.md`.
   * Point the derivation comments (`cpu.c`, `dispatch.c`, `vfpu.c`) at `14749c1`, after checking upstream's changes to those sources in `5ca18fa..14749c1`.
4. **Probe**: take item 9 of reDMP1's `tests/recomp_abi_probe.cpp`. It checks four things:
   * tail chains run to the end
   * the frame is restored
   * unwinds are cleared or kept correctly
   * an unregistered address reports a miss
5. **Regenerate**: run `scripts/recomp/regenerate.py` with the freshly built lifter, and check that the printed lifter path is the one just built. Generated code is not committed.
6. Docs: the psprecomp pin in `THIRD_PARTY_NOTICES.md` and the lifter baseline in `docs/analysis/executable.md`.

## 4. Verification

1. Compare generated code against the current output, with addresses removed and lines counted by frequency.
   * Expected: only the substitutions of reDMP1 §2. `psp_run(psp_func_X)`, `psp_import_X()` and `psp_dispatch(_t)` become `psp_call_guest_fn` / `psp_call_guest_addr`, and the header's `PSP_CALL_BEGIN`/`END` change.
   * Any other difference gets its cause written down.
2. Lift numbers are unchanged:
   * 7,982 functions
   * 28,109 entries
   * 759,072 B of `.text`
   * `lift_audit` 0/0

   Lifting reDMP1's PRX with this repository's lifter (a read-only measurement) matches reDMP1 v0.0.31's result (9,024 functions), so `0007` to `0011` leave the PRX path alone.
3. CTest: Win64 Debug/Release without generated code, and Release with generated code. Linux in CI.
4. Game: with v0.0.5's input script (`--max-vblanks 2400`), both Release and Debug (unoptimized generated code) reach the title screen, with no dispatch miss and no stack overflow.
5. In the same runs, compare the mean frame interval with v0.0.5 (each call goes through one more function).
