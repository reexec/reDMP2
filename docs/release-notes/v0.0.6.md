# reDMP2 v0.0.6

Moves psprecomp to upstream v0.6.0. Generated code changes only in the guest-call form; the lift result and boot path are unchanged.

Issue [#10](https://github.com/reexec/reDMP2/issues/10):

- `third_party/psprecomp` `5ca18fa` → `14749c1` (v0.6.0).
- Local patches now upstream are removed: `0001` (#36), `0003` (#31), `0004` (#35), `0006` (#38).
- `0005` is reDMP1's v0.6.0 rebase; `0007` to `0011` are regenerated on v0.6.0 with unchanged content.
- The ABI adapter gains `psp_call_guest_fn` / `psp_call_guest_addr` (#32), with probes.
- Generated code differs only in the #32 and #38 forms (nothing unexpected).
- 7,982 functions, 28,109 entries and `lift_audit` 0/0 are unchanged.
- Release and Debug both reach the title screen (Release mean frame interval 36.55 ms, v0.0.5 36.35 ms).
- Squashed into this release's merge commit.

Verified: CTest 31/31 on Win64 Debug/Release without generated code and 32/32 with it, zero warnings. Linux x64 in CI.
