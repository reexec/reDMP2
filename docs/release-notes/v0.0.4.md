# reDMP2 v0.0.4

Fixes the stall after the first frame; the boot now reaches the opening movie.

Issue [#6](https://github.com/reexec/reDMP2/issues/6):

- Cause, measured: the original has no busy wait. It was an infinite loop made by the lifter dropping `return;` after a `j <import>` (`$ra` `0x0882FB74`; diagnostic `REDMP2_TRACE_NID`, off by default).
- Local psprecomp patches:
  - `0009`: always `return;` after `j <import>`.
  - `0010`: import stubs leave the function list and are registered in the dispatch table as `psp_import_*`.
- Lift: functions 8,014 → 7,978 (36 stubs removed); `lift_audit` mismatches 12 → 0.
- `third_party/repsp` → v0.0.32 (`a730166`, [reexec/repsp#69](https://github.com/reexec/repsp/issues/69)): expired timed waits wake at safe points, so the sound thread no longer starves.
- 600 vblanks present 297 frames instead of 1, and `opening.pmf` plays (302 AVC and 225 ATRAC decodes).
- The patch README's upstream table is updated (as of psprecomp v0.6.0; submissions on hold).
- Squashed into this release's merge commit.

Verified: CTest 30/30 on Win64 Debug/Release without generated code (the CI condition), 32/32 on Release with generated code. Linux x64 in CI.
