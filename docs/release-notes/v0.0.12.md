# reDMP2 v0.0.12

Link disc works through a UMD swap. Insert another disc kept under `roms/` (for example `roms/ULKS46050/`, DJMAX Portable) from the OSD, then reinsert DMP2 when done.

Issue [#23](https://github.com/reexec/reDMP2/issues/23):

- Flow analysis (`docs/analysis/link-disc.md`):
  1. `LINK DISC` on the title, then confirm.
  2. Link data is extracted to the Memory Stick through the savedata utility (`ULKS46116DATA0/SD2.BIN`, `ULKS46116DATA1/SD3.BIN`).
  3. Replacement is permitted, and the game polls `GetDriveStat & 0x20`.
  4. The `PARAM.SFO` disc ID is checked.
  5. Play uses the inserted disc's `all.mp` and `all2.mp`.
  6. DMP2 is reinserted.
- OSD Info tab Link disc section:
  - drive state
  - insert per disc
  - reinsert DMP2
  - disabled, with the reason shown, while the game does not permit replacement
- `--insert-disc <vblank>:<disc_id|main>`.
- **`--save-dir` now means the Memory Stick root**: default `<user_data>/ms0`, with saves in `PSP/SAVEDATA`. Saves in the old default (`<user_data>/savedata`) are moved on first run.
- `third_party/repsp` → v0.0.37:
  - [reexec/repsp#79](https://github.com/reexec/repsp/issues/79): UMD swap model
  - [#80](https://github.com/reexec/repsp/issues/80): savedata modes, `sceIoDevctl`, volatile memory
- Without other discs only link disc is unavailable.
- Squashed into this release's merge commit.

Verified (headless): link disc with DMP1 through entry, swap, one link-mode song to completion, DMP2 reinsert and save. User check in windowed mode. CTest 35/35 on Win64 Release with generated code, 33/33 on Debug/Release without it. Linux x64 in CI.
