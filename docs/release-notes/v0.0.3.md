# reDMP2 v0.0.3

Lifts the function pointers an `ET_EXEC` builds in code, and pins repsp v0.0.31 (boot-path HLE); the boot reaches its first frame.

Issue [#5](https://github.com/reexec/reDMP2/issues/5):

- Local psprecomp patches:
  - `0007` turns on the `.text` lui+addiu pointer scan for `ET_EXEC`.
  - `0008` also scans the bodies of functions found outside `.text`.
- Lift results:
  - functions 7,933 → 8,014
  - `.text` coverage 97.5% → 98.2%
  - jump tables 355 → 365
  - no data misread as code
  - reDMP1's (PRX) lift is unchanged
- `third_party/repsp` → v0.0.31 (`0249592`, [reexec/repsp#67](https://github.com/reexec/repsp/issues/67)).
- Boot: runs to the 600-vblank limit, presents the first frame, 3 threads, opens `all.mp`/`all2.mp`.
- Squashed into this release's merge commit.

Known issue: nothing happens after the first frame (#6; repsp's scheduler does not wake expired timed waits during a busy loop, [reexec/repsp#69](https://github.com/reexec/repsp/issues/69)).

Upstream: the `0007` fix is also needed in [sp00nznet/psprecomp#36](https://github.com/sp00nznet/psprecomp/pull/36) (undecided).

Verified: CTest 30/30 on Win64 Debug/Release without generated code (the CI condition), 32/32 on Release with generated code. Linux x64 in CI.
