# reDMP2 v0.0.1

The first release: the bootstrap of the static recompilation project for DJ Max Portable 2 (Korea build `ULKS-46116`, 1.09, [redump #33115](http://redump.org/disc/33115/)). Structure, rules and code are ported from [reexec/reDMP1](https://github.com/reexec/reDMP1) v0.0.30 (`dadb6da`).

Issue [#1](https://github.com/reexec/reDMP2/issues/1): the rules and documents (as reDMP1's), the design and work order with review; the submodules `third_party/repsp` (v0.0.29, `7f856eb`) and `third_party/psprecomp` (`5ca18fa`); the psprecomp ABI adapter copied from reDMP1 (user decision); the title layer (`dmp2` profile, `variants.json`) and the `redmp2` app (without autoplay); `regenerate.py` handling an `ET_EXEC` lift input; the static import coverage tool `tools/import_coverage.py`; analysis of the disc, the executable and the first boot (`docs/analysis/`); CI and the release workflow. The commits on task branch `i001-project-bootstrap`, squashed into this release's merge commit.

Executable analysis (**confirmed**): `BOOT.BIN` is the plain `ET_EXEC` `djmax` fixed at `0x08804000` (DMP1's is a relocatable PRX), with 7,933 functions, 27,936 internal entries, 97.5% `.text` coverage, 355 jump tables (none unresolved) and 229 imported functions from 27 libraries (141 implemented by repsp, 88 missing).

Known issue: repsp `7f856eb`'s loader accepts only PRX modules, so a run stops at `LoadPrx failed: Unsupported ELF type`, and the two local CTest tests that need game data (`app_smoke_registered_roms`, `app_lift_check`) fail. Follow-up: `ET_EXEC` loading in repsp.

Verified: build (zero warnings in reDMP2 code) and CTest 30/30 without game data on Win64 Debug/Release (Visual Studio 17 2022, x64); 30/32 with generated code (the known issue above). Linux x64 in CI.
